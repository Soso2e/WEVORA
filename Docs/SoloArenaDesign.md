# WEVORA — ソロ・アリーナ／属性の試練 設計方針

> 決定日: 2026-10-17 / Status: **設計方針の合意**（未実装部分を含む）
>
> この文書はソロプレイの新しい優先方針。従来の `GAME_DESIGN.md` / `ROADMAP.md` に記載されている「対戦中心」「強化方式未決定」といった記述は、**ソロの販売・体験設計の優先順位については本書が後発の判断**。既存の技術的検証課題やオンライン構想そのものを削除するものではない。

## 1. 作品の方向性（決定）

- **Steam有料販売で、ソロプレイだけでも十分楽しめる**作品にする。マルチがなくても成立するゲーム体験を先に設計・検証する。
- ジャンルの核は **高速空中戦 × 自由に魔法を編むアクション × アリーナ型ローグライト**。
- **雑魚戦は殲滅の爽快感、強敵・ボス戦は回避・距離・編み・属性選択の駆け引き**を中心にする。
- **基本の魔法は簡単に扱え、上級者は操作技術と戦術で差が出る**。複雑な入力ができない人を排除しない。
- **高速で飛びながら自由に編める**ことを基本とする。飛行速度・加速方向などの運動状態が魔法に影響する要素は部分的に導入を検討するが、通常操作の自由を損なわない。

## 2. ステージ／1ラン（決定）

- **単一の大きなアリーナ**を基本とする。部屋の連結や多数のマップ制作を前提にしない。
- **ハイブリッド・ウェーブ制**：ウェーブ中は敵が連続的・段階的に追加出現し、終了条件を満たすと戦闘を区切る。
- 区切りの後に**強化を選択**して次ウェーブへ。難度の上昇に伴い敵の種類／数／出現位置／組み合わせを変化させる。
- 最終的には**雑魚戦 → 強化 → 強敵／中ボス → さらに強化 → 属性試練のボス**という戦闘サイクルを成立させる。
- 単一アリーナを再利用し、試練ごとの敵・ボス・光／演出などを切り替えて制作コストを抑える。
- **試練はクリア後も再挑戦可能**にする方向。ラン内の戦績・ベスト記録は今後の仕様検討項目。

## 3. 3系統の強化（決定）

### A. 属性（Element）
- 例：属性追加、攻撃範囲拡大、貫通、弾数、効果時間など。
- **属性反応を特定の強化カードで解禁・封印・制限しない。** 使用できる属性と有効な対象状態の組み合わせで、基本ルールとして発動できる。
- 各属性・形状の組み合わせが自動的に上位互換とならず、役割が変わることを重視する。
- 「属性追加」が*ラン内の属性選択肢の追加*なのか、*個々の魔法への属性合成*なのか、具体的なUI／上限／抽選条件は未確定。永続解放と混同しないよう整理する。

### B. 移動（Mobility）
- 例：移動速度、飛行加速、マナ回復速度、消費効率、機動中の編み性能など。
- 高速飛行の自由度と攻撃操作の一体感を損なわない。

### C. 生存（Survival）
- 例：HPの即時回復、最大HP上昇、最大マナ上昇、被ダメージ軽減など。
- 回復と上限UPはこの系統に集約する。

**共通原則**：原則としてこれらの強化は**1ラン限り**で、リトライ時には元に戻る。強化候補の具体的な提供数・頻度はテストして決定する。

## 4. 永続解放と属性の試練（決定）

- **開始時に使用できる属性は炎 (Fire) と風 (Wind)**。
- 「累計クリア数に応じて順に解放」ではなく、**特定の試練をクリアすると、その試練に対応する属性を永続的に習得する**。
- 例：**水の試練を初回クリア → 水属性を永続解放**。
- 解放済みの属性は**次のラン開始時から使用できる**方針（以前の提案を承認済み）。ラン内強化とは別管理する。
- 解放後も各試練は再挑戦できる設計を目指す。
- 雷 (Lightning) は戦闘用の試作実装が存在するが、**正式ソロプレイで初期解放済みという意味ではない**。試練による解放候補。
- 水・雷・土などの**具体的なラインアップ、解放順、各ボス詳細は未確定**。水は例示された試練の代表例。

## 5. 戦闘の原則（決定）

- 基本操作：通常攻撃、チャージ、編み、属性選択、飛行を状況に応じて使い分ける。
- 既存の4形状（Thrust / Sweep / Circle / Slam）を基礎とし、強化で性質が変わる。
- **属性反応はアップグレードで縛らない。** 少数の基本ルールから戦術的な組み合わせを生む。
- 雑魚戦は連続撃破・集団処理のテンポ、ボスは予兆への対応・回避・位置取り・反撃の判断を重視する。
- 威力の数値だけをインフレさせず、形・属性・移動・プレイヤースキルの組み合わせが意味を持つようにする。

## 6. 現行実装との接続（2026-10-17確認）

- **PR #7** は `work` の戦闘ベースラインを `main` に統合済み。
- **PR #8**（`feature/combat-playground`）は *Draft・未マージ*。一つの検証場、5対象、円形レティクル、偏差射撃、4形状の攻撃、Charge/Core/Trail/Burst、HUDなどが追加され、記録上の自動テストは **33/33成功**。
- **重要**：PIE／パッケージでの実入力、飛行・狙い・ジェスチャー・演出・楽しさの人間による検証は残っている。自動テスト成功を「面白さの検証完了」と見なさない。
- ソロウェーブ、3択強化、永続解放、属性試練ボスの**実装完了はまだ確認していない**。

## 7. 次の縦切り（提案・数値は未決定）

最初から製品分量にせず、Combat Playgroundで以下の最小サイクルを検証する：

1. 戦場の開始／ウェーブ管理（増援出現・同時敵数制限・終了判定）。
2. ウェーブクリア後の強化UI・3択選択・強化適用／ラン終了時リセット。
3. 属性／移動／生存の各系統から、挙動を比較できる少数の強化を用意。
4. 明確な予兆と隙を持つ簡易ボス1体を用意。
5. クリア・敗北・再挑戦・試練達成時の属性解放と永続保存をつなぐ。
6. 解放済み属性が次のラン開始時に利用できること、未解放属性が不意に恒久利用可能にならないことを検証。
7. 属性反応が強化未取得の状態でも正常に利用できる回帰テストを用意。
8. UE Win64ビルド／自動テストに加え、人間のPIE・パッケージ実プレイで面白さを評価。

**初期試作サイズの例**：5ウェーブ／3択強化／ボス1体。**これは仮説で、確定したウェーブ数やラン時間ではない。**

## 8. 保留事項（実装担当は勝手に確定しない）

- ソロ1ランの正式ウェーブ数、所要時間、ウェーブ終了条件、失敗時の復帰。
- 強化の具体的な数、抽選ロジック、3択表示頻度、同じ強化の重複・上限。
- 「属性追加」の具体的意味と初期選択UI（すでに永続解放済みの全属性をいつ選べるかの実装UX）。
- 試練ボスの種類・数・登場順、属性以外の報酬、高難度・スコア要素。
- 属性一覧・属性反応詳細・属性反応の命中部位との接続。
- マルチプレイの最終収録範囲・制作タイミング。**ソロ優先**であって、従来のマルチ案を撤回したという意味ではない。
- Steamの価格／発売日／発売時コンテンツ数。
